# redux-retry

Local loading, success, error and manual retry state for Redux sagas and thunks.
Use the `Retry` render-prop component or the `useRetry` hook. No extra reducers are required.

- Repository and source: https://github.com/nimeshgurung/redux-retry
- Quick start: https://github.com/nimeshgurung/redux-retry/blob/master/README.md
- API reference: https://github.com/nimeshgurung/redux-retry/blob/master/API.md
- Changelog: https://github.com/nimeshgurung/redux-retry/blob/master/CHANGELOG.md
- npm metadata: https://registry.npmjs.org/redux-retry

## Install

Install stable `1.0.1` for the modern component and hook APIs.
It uses the `next` npm channel during rollout; `latest` remains legacy `0.0.7`.
Use `redux-retry@next` to follow the modern channel, or pin `redux-retry@1.0.1` as below.
The earlier `1.0.0-beta.1` prerelease remains available for beta consumers.
Do not install the older `0.0.x` release for the hook API. Check published versions with:

```sh
npm view redux-retry versions --json
```

```sh
npm install redux-retry@1.0.1 react@^19 react-dom@^19 react-redux@^9 redux@^5 @reduxjs/toolkit
```

React 18 is also supported. The modern baseline is React 18/19, React Redux 9 and Redux 5.
For sagas, also install `redux-saga@^1`. Redux Toolkit supplies thunk middleware by default.

## Working thunk example

Use `redux-retry/thunk` when the application does not install saga middleware.
Both the hook and default component must render inside a React Redux Provider.

```jsx
import { configureStore } from '@reduxjs/toolkit';
import { createRoot } from 'react-dom/client';
import { Provider } from 'react-redux';
import { useRetry } from 'redux-retry/thunk';

const store = configureStore({ reducer: (state = {}) => state });

const loadProfile = (id) => async () => {
  const response = await fetch(`https://jsonplaceholder.typicode.com/users/${id}`);
  if (!response.ok) throw new Error(`Request failed: ${response.status}`);
  const profile = await response.json();
  return { name: profile.name, email: profile.email };
};

function Profile() {
  const [state, retry] = useRetry({ thunk: { call: loadProfile, args: [1] } });
  return (
    <section>
      {state.loading && <p>Loading…</p>}
      {state.error && <p>{String(state.exception)}</p>}
      {state.success && <p>{state.response?.name}</p>}
      <button disabled={state.loading} onClick={retry}>
        Retry
      </button>
    </section>
  );
}

createRoot(document.getElementById('root')).render(
  <Provider store={store}>
    <Profile />
  </Provider>,
);
```

## Component API

```jsx
import Retry from 'redux-retry/thunk';

<Retry thunk={{ call: loadProfile, args: [1] }}>
  {(state, retry) => (
    <button disabled={state.loading} onClick={retry}>
      {state.loading ? 'Loading…' : state.error ? 'Try again' : 'Refresh'}
    </button>
  )}
</Retry>;
```

## Saga setup

Import `Retry`, `useRetry` and `retryRoot` from `redux-retry` or `redux-retry/saga`.
Install saga middleware in the Redux store, then run `sagaMiddleware.run(retryRoot)` once.
Pass `{ saga: { call: generatorFunction, args: [argument] } }` to `useRetry`, or the same
`saga` prop to `<Retry>`. The root entry requires `redux-saga` to be installed.
Keep Redux Toolkit's default middleware checks enabled when adding saga middleware.

## API contract

- `useRetry(options)` returns `[state, retry]`.
- Supply exactly one of `saga` or `thunk`, with `{ call, args? }`.
- `call` is the saga generator function or thunk action creator, not its result.
- Calls start on mount unless `skipCallOnMount: true` is supplied.
- `state.loading`, `state.success` and `state.error` are booleans.
- `state.exception` contains the error value. `state.error` is not an Error object.
- `state.response` contains the successful result, and is initially undefined.
- `state.retryAttempt` starts at zero and increments on manual retry.
- `retry()` repeats the call; `retry([newArgument])` overrides arguments.
- Pass `retry` directly to a button handler; event arguments are ignored.
- Changed props are used on the next manual retry; they do not automatically trigger a request.
- Array call definitions run concurrently, preserve result order and fail the batch if one fails.
- Redux Toolkit async-thunk results are unwrapped into response or exception.
- Return values and arguments are inferred. Do not erase consumer types with explicit any.
- Named `Retry` supports explicit dispatch. Class refs and instance methods are not supported.
- Manual retry does not provide caching, automatic backoff or idempotency for write requests.
